## 项目范围扩展：AI 对话 → AI 对话 + 网页文档（v2.5 → 2.6）

用户要求把脚本从「只隐藏 AI 对话划词菜单」扩到「也隐藏网页文档里的工具栏」，第一个目标是语雀。

### 语雀规则
- DOM 样本存在 `dom/语雀.html`（用户给的是桌面上的原始 txt，已格式化落盘）。
- 结构：`div.wording-tooltip-module_toolTipContent__NHFlD` → 两个 `span.wording-tooltip-module_itemWrapper__1BQ9b`
  → 各含一个图标（`ne-icon-card-tb-comment`、`data-name="Note"`）。这是划词后的「评论 / 笔记」工具条。
- 选择器：`[class*="wording-tooltip-module_toolTipContent"]`（CSS 层）+ 兜底 `[class*="wording-tooltip-module"]`。
- host `/(^|\.)yuque\.com$/`，`@match https://*.yuque.com/*`。

### 关键判断
1. **工具条里没有任何文字**（纯文本内容为空），`textContent === ''` → keywords 校验必然失效。
   这是与 ChatGPT 那次「文案过期导致静默失效」相反的坑：不是文案改了，而是压根没文案。
   结论写进了 RULES 头部注释、README、以及技能 pitfalls §10。
2. **没有写 keywords**，因此两条选择器都进 CSS 层，不闪一帧。
3. 锚点刻意保留模块名 `wording-tooltip-module`，不放宽成 `[class*="toolTipContent"]`
   —— 页面别处还有别的 tooltip，语义名不是唯一标识。

### 域名
先问了用户地址栏真实域名（不猜）。用户确认 `yuque.com`。
起因：这份 DOM 里同时有 `ne-icon`（语雀 NE 设计系统）和 `larkui-icon`（飞书图标体系），
两个产品不该混在一起，所以没有凭产品名直接写 host —— 这是文心一言那次（yiyan vs wenxin）的教训。

### 测试
新增 `yuqueFixture()` 与断言 [13]~[16]，38 → **50 项**。覆盖：
- 哈希变化（`__NHFlD` → `__Xy8Qz`）仍命中；
- 模块级兜底能命中「只剩 itemWrapper」的残缺结构；
- 反例 `editor-tooltip-module_toolTipContent__k2P9a`（同语义名、不同模块前缀）必须保持可见；
- 域名边界：裸域 `yuque.com` 生效、`notyuque.com` 不注入。

反向验证两个方向都做了：放宽成 `[class*="toolTipContent"]` → 2 项失败（含误伤）；
选择器写坏 → 5 项失败。恢复后 50/50。

## 追加：编辑态工具条（v2.6 → 2.7）

用户又给了一份「编辑时的工具栏」DOM，存进 `dom/语雀-编辑态.html`。

- 结构：`div.ne-card-toolbar.ne-select-helper-toolbar`，两个 item 里分别是
  `IconAiTagNew`（AI 写作）和 `card-tb-comment`（评论）。同样纯图标、无文字。
- 新增 target：`[class*="ne-select-helper-toolbar"]`（CSS 层）。
- **关键取舍**：同元素上还挂着 `ne-card-toolbar`，但那是通用类——块级工具栏
  （段落左侧拖拽/复制/删除）也在用。拿它当锚点会把编辑器正常功能一起隐藏，
  且不会报错，只是"某个按钮点了没反应"。所以只认限定名。
- NE 的类名是 BEM 风格、没有构建哈希（不同于前面站点的 CSS Module），
  但类名顺序会变、会追加修饰类（`is-visible`），所以选择器不能依赖顺序。
- 测试 50 → **54 项**，新增断言 [15]：编辑态隐藏、类名乱序+追加类仍命中、
  块级工具栏不误伤。反例 `blockToolbar`（只挂 `ne-card-toolbar`）守住选择器不被放宽。
- 反向验证：改用 `[class*="ne-card-toolbar"]` → 2 项失败（含块级工具栏被误伤）；
  选择器写坏 → 3 项失败。恢复后 54/54。
- README 新增一段「一个元素常同时挂多个类名，要挑那个限定名」，目录树补 `语雀-编辑态.html`。

## 追加：腾讯文档编辑态（v2.7 → 2.8）

样本存 `dom/腾讯文档-编辑态.html`（原始 dump 37KB，已把 svg 内部路径压成 `<svg/>`，结构照抄）。

- 结构：`div.float-toolbar_container__zdDax` > `div[role=toolbar]`
  > 两个 `.toolbar-container.toolbar_container__3r-Et`：第一个多一个 `toolbar_hidden__2I957`
  （量宽度用的隐藏副本、`aria-hidden`），第二个才是显示的。
- 规则：`[class*="float-toolbar_container"]`（CSS 层）。域名 `docs.qq.com`（`/^docs\.qq\.com$/`）。
- **同一个坑第三次出现**：`toolbar_container__3r-Et` 是通用类，顶部固定菜单栏也挂它。
  必须是 `float-toolbar_container` 这个带限定词的。反例 `topToolbar` 守住这条。
- 隐藏整个 float 容器时那份量宽副本一起没了，宽度算 0；但工具栏本来就被藏，可见结果无影响。
  这点写进了代码注释，避免以后有人以为是 bug。
- 腾讯文档用的是 `dui-` 设计系统（dui-trigger / dui-dropdown / dui-badge），按钮上有稳定 id
  （`toolbar-button-bold` 等），但 id 是逐个按钮的，不适合当容器锚点。
- 测试 54 → **65 项**（新增 [18]~[21]）。
- 反向验证：改用 `[class*="toolbar_container"]` → 2 项失败（含顶部菜单被误伤）；
  写坏成 `float-toolbar_containerOLD` → 4 项失败。恢复后 65/65。
